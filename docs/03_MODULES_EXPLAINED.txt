03 - MODULES EXPLAINED
======================
Every package and file, in plain words. Paths are relative to vaultly/.

BACKEND ENTRY POINTS
--------------------
backend/cmd/server/main.go (+ keys.go)
  Loads config, builds the KeyProvider (keys.go: local or OpenBao, waits until OpenBao answers),
  connects Postgres (retries ~30 s), runs migrations, loads the PII keys and backfills old
  plaintext rows, connects Redis, creates the audit service and starts
  its consumer, hands everything to bootstrap.New (which builds repositories, services,
  handlers and routes), serves HTTP, runs the janitor, and shuts down gracefully on SIGTERM.

backend/cmd/vaultly/main.go
  The CLI. `pull` prints secrets (dotenv/shell/json), `run -- cmd` injects them
  as environment variables into a child process, `set KEY VALUE` writes one.
  Uses VAULTLY_TOKEN and VAULTLY_URL. Unwraps the API's {success,message,data} envelope.

backend/internal/config
  Reads environment variables into a Config struct. JWT_SECRET is mandatory (>= 32 chars);
  MASTER_KEY is mandatory only for KEY_PROVIDER=local; KEY_PROVIDER=openbao needs BAO_ADDR + a token.
  Also: DATABASE_URL, REDIS_URL, KAFKA_BROKERS, SMTP_*, APP_URL, CORS_ORIGINS,
  WEBHOOK_ALLOW_PRIVATE, RATELIMITER_URL.

backend/internal/db
  Connect() with retry; Migrate() runs every embedded migrations/*.sql in name
  order (001_init.sql, 002_features.sql, 003_encryption.sql). Migrations are idempotent (IF NOT EXISTS).

CRYPTO AND AUTH
---------------
backend/internal/crypto  (crypto.go, transit.go)
  KeyProvider interface = the root of trust: NewDEK / UnwrapDEK / Rewrap.
    Local    wraps with MASTER_KEY from the environment.
    Transit  talks to OpenBao's Transit engine over HTTP (the root key never leaves OpenBao).
    Hybrid   OpenBao for new keys, MASTER_KEY only to read keys not yet migrated.
  Encrypt/Decrypt = AES-256-GCM, output nonce||ciphertext, with "additional data".

backend/internal/pii  (pii.go)
  Encrypts personal data (emails, names, actor labels). Box.Seal/Open (AES-GCM, field name as
  additional data), Box.Index (HMAC blind index), Label/OpenLabel, Load (creates the two keys in
  app_keys, wrapped by the KeyProvider), Backfill (encrypts old plaintext rows at startup).

backend/internal/auth  (auth.go)
  HashPassword/CheckPassword (bcrypt cost 12). NewAccessToken/ParseAccessToken
  (HS256 JWT, 15 min, issuer "vaultly"). Refresh tokens: random 32 bytes, stored in
  Redis under sha256(token) for 7 days, consumed with GETDEL so each works once.

backend/internal/ratelimit
  limiter.go          Limiter interface + Result{Allowed, Remaining, ResetAt}
  sliding_window.go   Redis implementation (runs lua/sliding_window.lua atomically)
  lua/                the script: trim old entries, count, reject or add, set expiry
  remote.go           client for the standalone Distributed-rate-limiter service (RATELIMITER_URL);
                      registers a policy "vaultly-<limit>-<seconds>" on first use, falls back to the
                      local limiter if the service is unreachable

AUDIT, MAIL, WEBHOOKS
---------------------
backend/internal/audit  (audit.go)
  Event struct; Service.Publish (Kafka, with DB fallback); Service.Run (create topic,
  consume, insert, commit, notify); Subscribe() lets other modules react to events.

backend/internal/mail  (mail.go)
  Sender interface; SMTP implementation (multipart text+HTML) and a Log sender that
  prints the email when SMTP_HOST is unset. Header-injection guarded.

HOW EVERY DOMAIN IS BUILT   (backend/internal/<domain>/)
---------------------------------------------------------
  model.go        the structs that cross layer boundaries (and are returned as JSON)
  dto.go          request bodies with their `binding:` validation rules
  errors.go       sentinel errors, built with apperr (NotFound, Conflict, Invalid, Forbidden...)
  messages.go     every user-facing string, so wording lives in one place
  repository.go   ALL SQL for the domain; no business rules
  service.go      business rules, permission checks, audit events. Takes a principal.Actor and a
                  context, never a gin.Context. The repository is an interface declared here, so a
                  service can be tested with a fake.
  handler.go      binds the request, calls the service, answers with httpx.Success / httpx.Fail.
  Flow: routes -> middleware -> handler -> service -> repository -> PostgreSQL.
  Errors travel up as apperr values; httpx.Fail maps their kind to a status code in ONE place.

THE DOMAINS
-----------
user         register, login, refresh, logout, profile. Email/name sealed (pii), refresh cookie.
org          workspaces list/create, dashboard stats, environment slugs.
member       members, role changes, per-environment overrides (cannot demote the last admin).
invite       emailed single-use invitation links, preview and accept.
project      projects and environments; creating a project makes its data key.
secret       the core: versioned transactional writes, list/search, rollback, rotate, import/export,
             ${reference} resolver (resolver.go), .env parsing (dotenv.go), machine fetch/put.
token        service tokens (env + path scope, IP allowlist) and personal tokens; also the
             Authenticate* functions the middleware calls.
webhook      CRUD, test ping, delivery history; dispatcher.go signs (HMAC-SHA256 over
             "timestamp.body"), POSTs with retries, blocks private addresses at dial time (SSRF).
integration  GitHub / Vercel / Railway providers (providers.go) + CRUD, sync, debounced auto-sync.
dynamic      Postgres provider (provider.go) + dynamic secrets, leases, revocation.
backup       sealed export/restore; seal.go is the file format (gzip + scrypt + AES-GCM).
audit        publishes events to Kafka (DB fallback), consumes them, notifies subscribers, and
             serves the admin activity log (reader.go).

SUPPORT PACKAGES
----------------
access       OrgRole/ProjectWithRole and the per-environment rule: workspace role by default,
             member_env_roles override for that environment name.
keystore     unwraps a project's data key via the KeyProvider and caches it ~60 s.
principal    Actor{UserID, Email, ViaPAT, Token, IP}; placed on the request by the middleware.
middleware   CORS, security headers, UserAuth (JWT or vpt_), ServiceAuth (vst_ + IP allowlist),
             Limit(name, limit, window, key).
routes       one file per area; the only place URLs are written.
bootstrap    constructs repositories -> services -> handlers, wires audit subscribers
             (webhook dispatcher, integration auto-sync), picks the rate limiter, runs the janitor.
janitor      runs jobs every 20 s: revoke expired dynamic leases, announce expired secrets.
httpx        {success,message,data} envelope, validation errors, UUID params, timeouts.
apperr       Kind (Invalid, Unauthorized, Forbidden, NotFound, Conflict, Gone, Upstream).
pathutil     Norm/Join/Within for folder paths.   tokenutil  prefixed random credentials + hashing.
slug / dberr small helpers (slug text, Postgres error codes).

OPENBAO SETUP
-------------
openbao/bootstrap.sh   sidecar loop: init once, unseal after restarts, enable Transit, create key
                       "vaultly", write a least-privilege policy, issue the app token to a shared volume.
